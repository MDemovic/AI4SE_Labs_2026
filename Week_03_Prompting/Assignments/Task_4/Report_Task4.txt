Task 4 – Detailed comparison and interpretation

I compared the corrected ICIO, ReAct, and SCOPE prompts using the new Task 2 predictions and the recalculated Task 3 metric. All three prompts now request HOUSE_NUMBER and NAME. 
The first comparison used one fresh-session run per prompt with GPT-6.1 SOL and Medium reasoning, the same input files, and the same illustrative SQL example. I then ran each corrected prompt once with GPT luna, High reasoning, and Chat / Instant mode. I recorded the model and setting names as shown to me. Both the model and settings changed between the two comparisons.
The comparison includes the original evaluator’s exact-row accuracy, name-only exact matching, macro name F1, and observed generation time. 
The analysis and figures were prepared with help from a LLM.

With GPT-6.1 SOL Medium, all three prompts returned the same rows, including duplicate counts, for all 155 questions. Their SQL text differed on 129 questions for ICIO versus ReAct, 155 for ICIO versus SCOPE, and 155 for ReAct versus SCOPE. 
Initially, the prompts asked for restaurant ID and NAME, but the expected results contain HOUSE_NUMBER and NAME. The models followed our wrong instruction. I first thought the reference IDs were inconsistent, but that explanation was wrong.
After correcting the output columns and requiring the LOCATION join, I reran all three prompts. All 13,235 expected row occurrences match house-number/name pairs in the supplied database. The evaluator was not changed.

Comparison of the initial and corrected runs, applying to all three frameworks:
Run                 Original accuracy    Name exact match    Macro name F1
Initial prompts     27.74% (43/155)       92.26% (143/155)    98.49%
Corrected prompts   94.84% (147/155)      94.84% (147/155)    98.51%

The original accuracy increased by 67.10 percentage points. Name-based F1 changed only slightly because it ignores the numerical output column. The required join also changed some returned rows, so this was not simply renaming a column.
The improvement came from fixing the requested output, not from one framework being better. I spent part of the available time finding and fixing this mistake, then added the GPT luna / High / Instant runs. I did not have time for more prompt changes or repeated runs with the same settings.

Name-only exact matching now equals the original accuracy, with 8 questions failing both. F1 distinguishes partial overlap from complete failure: 147 questions scored 1, 6 scored between 0 and 1, and two scored 0. 
The high F1 therefore does not mean every question was answered correctly.

Looking only at questions with nonempty expected results lowers F1 from 98.51% to 97.94%. Empty matches help the overall score, but most names still match when these questions are left out. 
An empty match also cannot verify which columns the query selected.

The same table applies to all three GPT-6.1 SOL Medium runs. Full questions, missing and extra name counts, and SQL for each framework are stored in name_mismatch_examples.csv.
For all 6 partial matches, every expected name occurrence was returned, but additional occurrences were present. 
Some mismatches involve how the database represents restaurants rather than an obviously incorrect condition.

For questions 23 and 28, the extra occurrence is "genghis khan kitehen". The database stores two rows with that name, both in Alameda with rating 2.3, but under different cuisines and IDs. 
Both satisfy the requested rating above 2. The expected names contain one occurrence. 

Question 35 similarly includes an extra occurrence of "millie's kitchen", stored under both american and cafe. For these three questions, the distinct name sets match exactly; only the number of times each name appears differs.

This shows a limitation of the metric: it counts repeated names but cannot tell whether they are separate restaurants or different descriptions of the same one. 
Automatically applying DISTINCT to names would also risk combining genuinely different restaurants.

Question 121 asks for yogurt restaurants in Santa Rosa with rating above 1.7. The extra name is "checkers pizza & frozen yogurt", which is present in the supplied database under yogurt, 
Santa Rosa, with rating 2.0. Its inclusion follows the explicit filter. The mismatch does not by itself prove an interpretation error.

Question 66 asks "What is the lifes greates illusion?". All prompts returned an empty restaurant result, while the reference contains 2,696 rows. 
The question provides no clear restaurant criteria, so this mismatch does not clearly demonstrate a model error, but rather a potentially unsuitable question.

Question 131 asks for Thai restaurants in "unknown" with rating above 2.7. The queries treated unknown as a literal city, but the database has no such city. 
The expected names include restaurants in other cities. This suggests the reference may interpret unknown as an unspecified location. That is an ambiguity, not something syntax validation can resolve. 
A future prompt could explicitly define placeholder handling, but should do so consistently and without copying these particular answers.


Pointers that would help:
- Define how prompts should handle "unknown" locations and unrelated questions.
- Clarify whether queries should return database rows or unique restaurants.
- Add a distinct-name score alongside multiset F1 to separate duplicate-count differences from missing or extra names.

--- Additional runs: GPT luna / High / Instant ---

The same corrected prompts were used for these runs. Their CSV files and metadata are stored in ICIO_rerun, ReAct_rerun, and SCOPE_rerun. I did not record whether these additional runs all used fresh sessions, so I cannot confirm this for the comparison.

Framework    Accuracy       Correct    Name F1    Nonempty name F1    Time
ICIO         89.03%         138/155    93.42%     97.15%              61 s
ReAct        94.84%         147/155    98.51%     97.94%              52 s
SCOPE        89.03%         138/155    92.84%     90.10%              109 s

All 155 queries in each additional file executed successfully and returned HOUSE_NUMBER and NAME. ReAct returned exactly the same rows and duplicate counts as its Medium run. ICIO differed from its Medium run on 10 questions, and SCOPE differed on 9.

Unlike the Medium comparison, the additional prompt outputs differed. ICIO and ReAct differed on 10 questions, ICIO and SCOPE on 19, and ReAct and SCOPE on 9. ICIO and SCOPE had equal accuracy but different F1 scores, so the same accuracy did not mean the same answers.

Some failures were clear interpretation errors. In question 1, the additional ICIO query filtered the city Winters but omitted the requested tea cuisine, returning an unrelated restaurant instead of the expected empty result. In question 73 it omitted the street and city criteria and returned 9,538 rows. In question 135 it incorrectly treated parts of the distracting story as restaurant-name and city filters.

The additional SCOPE run also missed some filters. In question 116 it omitted the breakfast cuisine condition and returned 3,381 rows instead of 30. In question 108 it treated part of the unrelated story as the cuisine value. These examples show that SQL can run successfully and still answer the question incorrectly.

ReAct was fastest in these additional runs at 52 seconds and also had the best accuracy and F1. ICIO was faster than its Medium run but less accurate. SCOPE was both slower than its Medium run and less accurate. Changing the model and settings did not make all prompts faster or more accurate.

--- Comparison ---

I compared the prompts question by question because they answered the same questions.
The analysis used a paired permutation test, which checks whether swapping prompt labels within each question changes the average score difference. 
For the Medium runs, every question had the same score across prompts, so swapping labels changed nothing. The p-value was therefore 1 for every comparison.

Comparison       Original accuracy p   Name exact-match p   Name F1 p
ICIO vs ReAct    1.000                 1.000                1.000
ICIO vs SCOPE    1.000                 1.000                1.000
ReAct vs SCOPE   1.000                 1.000                1.000

Using a significance threshold of 0.05, there was no statistically significant quality difference between the Medium prompt runs. 
This applies to these saved outputs; it does not prove that the prompts would perform equally on other questions or repeated runs.
Generation times were different: ICIO took 74 seconds, ReAct 86, and SCOPE 101. 
However, one run per prompt is not enough to test whether these speed differences are consistent. The ±1 second describes stopwatch uncertainty, not variation between runs.


I also used the same tests for the additional runs and compared each prompt between Medium and GPT luna. This gives nine comparisons per metric: three between the Medium prompts, three between the Luna prompts, and three comparing the same prompt across both setups. I used Holm correction to account for doing several tests, separately for each metric. Full results are in additional_paired_comparisons.csv.

Using 0.05 as the cutoff, ReAct had significantly higher F1 than ICIO and SCOPE in the saved GPT luna runs. Medium also had significantly higher F1 than GPT luna for ICIO and SCOPE. The accuracy tests showed the same four differences, with adjusted p=0.03516. The other comparisons did not show significant differences.
For the ICIO-versus-SCOPE F1 test, I used 10,000 random label swaps with a fixed seed. The other listed F1 p-values are exact. Some questions are repeated or similar, and I only ran each prompt once per setup. The tests compare these saved answers; they do not show how the models would perform over many runs or prove that the reasoning settings caused the differences.

Prompts: All three used the same schema, example, output format, and similar SQL rules. These shared instructions may explain the identical Medium results. The additional GPT luna runs show that the outputs can still differ with another model and settings.
Since some rules also differed, this was not a comparison of framework structure alone.

Model: Each group used the same model and settings for all three prompts. But both the model and settings changed between the groups, so I cannot say which change caused the differences. More runs would be needed to see whether the results stay similar.
Coding agent and tools: Python execution can catch SQL errors, but a query can execute successfully while returning the wrong columns or interpreting an ambiguous question differently. The initial ID/HOUSE_NUMBER mistake is an example of this. 
ChatGPT does not expose its full internal reasoning (only partial reasoning summaries), so I could verify the generated SQL but not whether it followed every reasoning step requested by the framework. 

Timing: Extra checks, tool calls, and service delays may explain the longer runs. These are possible causes, not things measured in this experiment.

--- Interpretation ---

ICIO was fastest in the Medium comparison and achieved the same measured quality as ReAct and SCOPE. In the additional GPT luna comparison, ReAct was fastest and achieved higher accuracy and F1 than the other prompts. This does not mean that one framework is always the best.
If I continued, I would clarify the unclear questions and how to handle duplicates, keep tool access the same, and repeat each prompt several times.
